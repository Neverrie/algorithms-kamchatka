# Алгоритмы Камчатки

**Карта снега и дорог** — [запуск веб-приложения с нуля через Docker](README_CITY_SIM.md#запуск-с-нуля).

Стартовый репозиторий для пяти команд. На одной учебной смене сравниваем решения диспетчера: какую машину отправить первой, когда откроется критический проезд и какие работы из-за этого сдвинутся.

## Запуск за пять минут

Нужен Python 3.10 или новее. Откройте терминал в корне репозитория. После получения копии все команды ниже работают без сети, ключей и сторонних пакетов. На Windows можно заменить `python3` на `py -3`.

```sh
python3 --version
python3 -m unittest discover -s tests
python3 -m starter.cli --team team_01
python3 -m starter.cli --team team_01 --scenario no_compact
```

Подставьте номер своей команды от `team_01` до `team_05`. Для запуска только базового плана выполните `python3 -m starter.cli`.

В исходной версии базовый план открывает проезд в **06:53**, пример команды — в **06:24**, при сроке **06:35**. Оба выполняют 4 работы из 4, а холостые переезды занимают соответственно 6 и 22 минуты. В режиме `no_compact` оба плана оставляют узкий участок закрытым.

## Первое задание

1. Запустите оба сценария и найдите в выводе две работы, которые вместе открывают критический проезд.
2. В своей папке откройте `policy.py`. Для пробного изменения верните из `rank` кортеж `(candidate.transit, candidate.finish)`. Посмотрите, когда теперь откроется подъезд и сколько займут холостые переезды.
3. Сформулируйте свою гипотезу и сделайте первое изменение в своей ветке. Для простых правил достаточно менять `rank`. Если нужен другой способ планирования, реализуйте его внутри папки команды с точкой входа `plan(scenario) -> Plan`.
4. Попросите участника другой команды запустить ваше демо по инструкции. На демо покажите базовый и ваш план в обоих сценариях и объясните, какое решение вы предлагаете диспетчеру.

Параллельно команды могут собрать свои интеграции с картой, роутером и погодой. Стартовый пример запускается на учебных данных. Удачную интеграцию можно предложить другим командам в [shared/](shared/README.md).

В тройке один человек держит сценарий и контрольный пример, второй — расчёт, третий — запуск и демо. На вечерней проверке смотрим, соблюдены ли ограничения техники, во сколько откроется проезд, сколько работ выполнено и сколько времени ушло на холостые переезды.

## Что лежит в репозитории

| Путь | Назначение |
| --- | --- |
| `scenarios/district.json` | Общий учебный сценарий и условная матрица переездов. Для сопоставимого демо все запускаются на этой версии. |
| `starter/model.py` | Типы данных, базовый порядок из сценария и общий расчёт допустимых назначений. Чем меньше кортеж, который возвращает `rank`, тем выше приоритет назначения. |
| `starter/cli.py` | Загрузка сценария, запуск и таблица результатов. |
| `teams/team_01/` … `teams/team_05/` | Одинаковый рабочий пример на старте, дальше каждая команда дорабатывает свою папку. |
| `shared/` | Необязательные компоненты, которые команды предлагают друг другу. |
| `tests/` | Короткие проверки расчёта и запуска всех команд. |

В общей ветке изменения стартового кода и учебного сценария согласуют наставники. Команды работают в своих ветках, например `team-01/first-pass`, и могут заимствовать полезные компоненты друг у друга. Для общего компонента достаточно небольшого PR с примером запуска и именем команды-автора. Правила обмена описаны в [shared/README.md](shared/README.md).

## Как читать сценарий

Смена идёт с 06:00 до 07:00 по местному времени. `start` и `end` — индексы в `coordinates_lon_lat`. Строка матрицы — точка отправления, столбец — точка прибытия. Время в матрице и длительность работ указаны в секундах. `null` в матрице означает отсутствие допустимого переезда в модели. Проезд считается открытым после завершения **всех** работ из `access_jobs`. Холостое время включает переезды к назначенным работам. Возврат на базу в сценарий не заложен.

Координаты — пример точек в Петропавловске-Камчатском. Матрица, задания, парк и сроки придуманы для упражнения. Модель считает, что машина может совершать переезды, указанные в матрице. Для реальных улиц уточняйте зимние ограничения с дорожниками.

## Как запустить свой сценарий

Скопируйте `scenarios/district.json` в свою папку и сохраните в копию данные, собранные вашей интеграцией. Во входном JSON должны совпадать порядок координат, индексы начальных и конечных точек и порядок строк и столбцов матрицы. Список `access_jobs` содержит идентификаторы всех работ, нужных для открытия проезда.

```sh
python3 -m starter.cli --team team_01 --data teams/team_01/district.json
python3 -m starter.cli --team team_01 --data teams/team_01/district.json --scenario no_compact
```

В каждом запуске базовый план и план команды используют один JSON. Для общего сравнения команд запускайте штатный учебный сценарий. Для демонстрации интеграции покажите, какие данные она подставила и какое решение диспетчера изменилось.
