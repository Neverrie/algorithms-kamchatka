# JSON для аэродинамического решателя

Контракт 1.0. Возьмите реальный пример через `GET /api/v1/scenarios/{scenario_id}/solver-input` или кнопку «JSON для решателя». Типы запросов и ответов доступны в [OpenAPI](http://127.0.0.1:8008/openapi.json). При установленном `CITY_SIM_SOLVER_URL` FastAPI отправляет тот же JSON методом POST и ждёт ответ до 120 секунд. Сценарий и результат сохраняются по ID.

## Запрос

- `scenario_id`, `city_revision`, `request_hash`, `contract_version` идентифицируют сценарий и его входы. Одинаковый нормализованный набор входных данных даёт одинаковый SHA‑256 независимо от ID сценария.
- `region` задаётся как `west,south,east,north` в WGS 84. Полигоны зданий и сетка высот используют UTM 57N (EPSG:32657), метры, оси X на восток и Y на север. Первая граница полигона внешняя, последующие — отверстия. Контуры зданий на границе передаются целиком.
- `wind.speed_mps`, `wind.direction_from_deg`, `wind.reference_height_m` задают скорость и высоту входного ветра, а также направление, откуда он дует. Например, 270° означает приход с запада. Высота входного ветра задана над поверхностью.
- `buildings[].height_m` передаёт числовой тег высоты OSM при его наличии. Есть `height_verified`, `height_source` и `height_flags`. Для неизвестных и оценённых по этажности высот используется `null`.
- `terrain` задаёт сетку DSM с шагом 30 м и вертикальным CRS EPSG:3855 (EGM2008). `origin_xy_m` — юго-западный угол первой ячейки. Центры находятся на половине шага от границ. Массив идёт строками с юга на север, внутри строки с запада на восток. `null` означает отсутствие значения. Само поле `terrain` может быть `null` для неподготовленной установки.
- `available_loose_snow` и `weather` сохраняют исходные условия сценария и происхождение погоды.

## Ответ

Минимальный пример структуры. Числа здесь иллюстрируют формат передачи.

```json
{
  "model_name": "danil-wind",
  "model_version": "0.1.0",
  "source_kind": "physical_solver",
  "request_hash": "<SHA-256 из запроса>",
  "grid": {
    "crs": "EPSG:32657",
    "origin_xy_m": [476000, 5876000],
    "cell_size_m": 20,
    "width": 2,
    "height": 1,
    "reference_height_m": 10,
    "vertical_reference": "above_dsm",
    "order": "row_major_south_to_north"
  },
  "pressure_reference": "gauge",
  "pressure_pa": [-1.2, 0.6],
  "velocity_east_mps": [4.7, 3.1],
  "velocity_north_mps": [0.3, 0.2],
  "velocity_up_mps": [null, 0.1]
}
```

Хотя бы один массив должен присутствовать. Длина каждого массива равна `width × height`, максимум 250 000 ячеек. `null` — маска или пропуск. Векторы направлены на восток, север и вверх. Давление в паскалях с обязательным указанием `gauge` или `absolute` при наличии массива давления. Для пространственного просмотра скорость требует обеих горизонтальных компонент. Конец стрелки показывает направление потока.

`GET /api/v1/runs/{run_id}` возвращает полный результат. `.../field` даёт облегчённую выборку с координатами WGS84 для визуализации. `.../assets` привязывает численные значения к стабильным ID, беря ячейку в середине направленной дуги или координате объекта инфраструктуры. Выход содержит регистр графа, высоту слоя, тип давления и метод выборки. Операционная оценка риска — отдельный этап.

`SnowDriftModel` определяет границу для будущей модели переноса снега. Результат связывается с аэродинамическим расчётом через `wind_run_id`, задаёт интервал времени и изменение массы снега на единицу площади. Для использования нужны данные о снежном покрытии, критерии начала переноса и независимая проверка.

## Вопросы для Данила

1. Какой минимальный вход получается из твоих симуляций — полигоны квартала, размеры и ориентация зданий или заранее рассчитанные шаблоны? Нужна ли буферная зона вокруг расчётного тайла и какого размера?
2. Какая высотная привязка и высоты слоёв? Нужен ли профиль скорости вместо одного значения на высоте 10 м? Где заданы граничные условия?
3. Какая сетка выходит из солвера? Доступны ли компоненты скорости, давление и параметры турбулентности? Относительно чего вычисляется давление?
4. Как обрабатывать контуры с неизвестной и непроверенной высотой? Нужна ли маска зданий на выходе?
5. Сколько памяти и времени занимает один тайл и насколько стабилен результат при смене шага? Влезает ли первый двухветровой пример в синхронный интерфейс?
6. Есть ли выходные данные о переносе снега? Если да, в каких единицах и с какими входами о покрытии?

Для первой интеграции подойдут два расчёта на одном квартале с противоположным направлением и одинаковой скоростью ветра. Сравним координаты, маски, экстремумы и привязку полей к дорогам.
